## 1. Краткое резюме

### 1.1. Что появилось

В MediaWatch добавлены четыре самостоятельных раздела в заданном порядке:

**Подкасты → Книги → Ранобэ → Манга**

| Раздел | Источник | Маршрут | Формат чтения/прослушивания | Прогресс |
|---|---|---|---|---|
| Подкасты | iTunes Search + RSS шоу | `/podcasts` | встроенный `<audio>`-плеер | эпизод + секунда |
| Книги | Флибуста через OPDS | `/books` | EPUB через epub.js, FB2 через серверный парсер | `percent` + CFI/scroll |
| Ранобэ | Renovels API | `/ranobe` | встроенный читатель главы | глава + scroll |
| Манга | Remanga API | `/manga` | вертикальная лента страниц | глава + scroll/page |

Порядок в навигации сохранён: подкасты идут после аниме/кино, затем книги,
ранобэ и манга. Это не «версии для кино» и не подразделы каталога — у каждого
свой источник, свой индекс и свои маршруты.

### 1.2. Главный архитектурный результат

Новые разделы не потребовали второй архитектуры приложения. Они переиспользуют
уже существующую модель:

**тайтл → юнит (серия / эпизод / глава / страница) → позиция внутри юнита**

Общими остались:

- `watch_progress` — текущая позиция и «Продолжить»;
- `watched_episodes` — отметки о прослушанных/прочитанных юнитах;
- `user_list` — списки пользователя;
- `/api/progress` — единая точка сохранения;
- `/api/proxy/raw` — подписанный прокси для аудио, обложек и страниц;
- Supabase-клиенты, RLS, service-role для кронов;
- паттерн «собственный индекс + ночная пересборка» для каталогов;
- общие компоненты карточек, поиска и «Продолжить».

### 1.3. Что сделано

- 6 миграций: `0051`–`0056`;
- 4 пары «источник + индекс»: подкасты, книги, ранобэ, манга;
- клиентобезопасные shared-модули типов и подписей;
- 13 новых страниц;
- 17 новых компонентов;
- 4 крона пересборки;
- общий модуль прогресса чтения;
- расширение `/api/progress` под `book`/`ranobe`/`manga`;
- навигация в шапке и нижнем доке;
- админ-секции и ручной запуск пересборок;
- README и отдельная справка `MANGA.md`;
- успешные `tsc`, `next lint` и `next build`.

### 1.4. Что не завершено

- миграции `0053`–`0056` не применены в рабочей БД; статус `0051`/`0052`
  нужно подтвердить;
- индексы не пересобраны в рабочей среде;
- VPS-кроны для новых разделов не настроены;
- нет проверки под тестовым авторизованным пользователем;
- нет полноценного живого прогона книг, ранобэ и подкастов после применения
  схемы;
- адаптивность на 375 / 1024–1279 / 1280+ проверена только по коду, не на
  реальных устройствах.

## 2. Исходная задача и ограничения

### 2.1. Задача

Довести расширение MediaWatch разделами:

1. подкасты;
2. книги;
3. ранобэ;
4. манга.

Требования:

- книги, ранобэ и манга читаются во встроенном ридере, без перехода на
  внешние сайты для чтения;
- пользовательских загрузок нет: контент берётся только у внешних источников;
- «всё, даже платное» — по возможности показать максимум контента;
- контент со всех регионов;
- в БД хранить только id и лёгкие метаданные, не хранить тяжёлый контент;
- поиск по подстроке, например «реализация ии»;
- прогресс общий, через `watch_progress` / `watched_episodes` / `user_list`;
- подготовить полный `.md`-отчёт по всей сессии.

### 2.2. Как ограничения были выполнены

| Ограничение | Результат | Комментарий |
|---|---|---|
| Порядок разделов | Выполнено | Подкасты → книги → ранобэ → манга в шапке и доке |
| Встроенный ридер | Выполнено | EPUB/FB2, глава ранобэ, лента манги |
| Без пользовательских загрузок | Выполнено | Контент только из внешних источников |
| «Всё, даже платное» | Выполнено частично и честно | Платные главы видны, но не читаются без покупки у источника |
| Контент со всех регионов | Выполнено частично | Подкасты — 19 регионов iTunes; книги/ранобэ/манга — в основном русскоязычные/азиатские каталоги источников |
| Только лёгкие метаданные | Выполнено | В индексах id, названия, автор, обложка, рейтинг, число глав и т. п. |
| Поиск по подстроке | Выполнено | `pg_trgm` по индексам + живой поиск источника |
| Общий прогресс | Выполнено | Единый `/api/progress`, `watch_progress` и `watched_episodes` |
| Отчёт `.md` | Выполнено | Этот файл + `MANGA.md` |

### 2.3. Важное уточнение про платный контент

Требование «всё, даже платное» **нельзя выполнить обходом защиты источника**.
Это не техническое упущение, а физическое ограничение:

- Remanga для платной главы отвечает `401`, картинки не приходят;
- Renovels для платной главы отдаёт `is_paid = true` и пустой `content`;
- у Флибусты платность не является отдельным API-флагом, но файлы могут
  отсутствовать или быть недоступны.

Поэтому реализовано корректное поведение:

- платная глава **видна** в оглавлении;
- она помечена как заблокированная;
- читатель не делает запрос страниц, если глава платная;
- прогресс по такой главе не сохраняется как прочитанный;
- если источник сам разрешает главу сегодня (`is_free_today` у Remanga), она
  открывается на общих основаниях.

Это честнее, чем имитация доступа или скрытие платных глав.

## 4. Общая архитектура

### 4.1. Схема

```text
┌──────────────────────────────────────────────────────────────┐
│ Внешние источники                                            │
│ iTunes / RSS · Flibusta OPDS · Renovels API · Remanga API    │
└───────────────┬──────────────────────────────────────────────┘
                │ live-запросы
                ▼
┌──────────────────────────────────────────────────────────────┐
│ src/lib/*.ts                                                 │
│ нормализация, кэш, поиск, карточка, главы, страницы          │
└───────┬───────────────────────────────┬──────────────────────┘
        │                               │
        │ ночной крон                   │ серверный рендер
        ▼                               ▼
┌───────────────────────┐      ┌───────────────────────────────┐
│ Индексы каталогов     │      │ Страницы и читатели           │
│ podcast_index         │      │ /podcasts /books /ranobe      │
│ book_index            │      │ /manga                        │
│ ranobe_index          │      │ встроенные плееры/ридеры      │
│ manga_index           │      └──────────────┬────────────────┘
└───────────┬───────────┘                     │
            │                                 │
            └──────────────┬──────────────────┘
                           ▼
              ┌──────────────────────────────┐
              │ /api/progress                │
              │ watch_progress               │
              │ watched_episodes             │
              │ user_list                    │
              └──────────────────────────────┘
```

### 4.2. Почему не появилась `content_items`

Отдельная универсальная таблица контента не заводилась. Причины:

- у существующих таблиц уже есть ключ `(content_type, shikimori_id)`;
- числовой id источника помещается в `bigint shikimori_id`;
- `content_type` различает пространства id;
- `source` позволяет указать происхождение там, где это важно;
- отдельная таблица потребовала бы миграции всех связей, RLS, social,
  прогресса и истории.

Для книг id Флибусты, для ранобэ id Renovels, для манги id Remanga — все они
лежат в `shikimori_id` с соответствующим `content_type`.

### 4.3. Два типа индексов

В проекте используются два разных приёма:

**Сменяемая партия (`batch_id`)**

- `podcast_index`;
- `anime_index`, `cinema_index` — по той же схеме;
- крон пишет новую партию, затем переключает `active_batch`;
- оборванный прогон не ломает текущий каталог.

**Постоянный кэш (`in_catalog` + `rank`)**

- `book_index`;
- `ranobe_index`;
- `manga_index`;
- строки не удаляются, потому что по ним открываются карточки и «Продолжить»;
- крон обновляет `in_catalog` и `rank`, а старые метаданные остаются.

Такое разделение — не случайность. У подкастов и видео каталог можно заменить
целиком. У книг, ранобэ и манги карточка часто открывается **только по записи в
индексе**, поэтому удалять старые строки нельзя.

### 4.4. Деградация при недоступности источника

Общий принцип: страница должна показать хоть что-то, даже если API источника
лежит.

- каталог читается из индекса;
- карточка может быть собрана из сохранённых метаданных;
- поиск сначала идёт по индексу, затем — живой поиск источника;
- главы и страницы запрашиваются live, но ошибка не кэшируется на полчаса;
- при отсутствии `PROXY_SIGNING_SECRET` ссылка на обложку откатывается на
  прямой URL, чтобы локальная сборка не показывала пустые заглушки.

## 5. Общий прогресс

### 5.1. Миграции

**`0051_podcasts.sql`**

- `shikimori_id` переведён в `bigint` во всех таблицах прогресса;
- разрешён `content_type = 'podcast'`;
- Apple `collectionId` бывает больше `int32` (например, `6822037200`).

**`0053_books.sql`**

Расширяет:

- `content_type` до `book`, `manga`, `ranobe` (плюс уже существующие
  `anime`, `cinema`, `podcast`);
- `source` в `watch_progress`, `user_list`, `watched_episodes`;
- `unit`, `progress_percent`, `locator` в `watch_progress`;
- constraint’ы в `episode_notifications`, `title_ratings`,
  `episode_comments`.

Допустимые `unit`:

| `unit` | Для чего | Где позиция |
|---|---|---|
| `seconds` | видео, подкасты | `position_seconds` |
| `percent` | книги | `progress_percent` + `locator` |
| `chapter` | ранобэ | номер главы + `locator` |
| `page` | манга | глава/страница + `locator` |

### 5.2. Таблица типов

| `content_type` | Внешний id | `source` | `unit` | `episode` | `progress_percent` | `locator` |
|---|---|---|---|---|---|---|
| `podcast` | Apple `collectionId` | `null` | `seconds` | номер выпуска | — | — |
| `book` | id Флибусты | `flibusta` | `percent` | `1` | доля книги | `cfi` или `scrollPercent` |
| `ranobe` | id Renovels | `renovels` | `chapter` | индекс главы | общий процент | `dir`, `chapterId`, `chapterIndex`, `chapterLabel`, `scrollPercent`, `chaptersCount` |
| `manga` | id Remanga | `remanga` | `page` | индекс главы | общий процент | `dir`, `chapterId`, `chapterIndex`, `chapterLabel`, `page`, `pagesCount`, `scrollPercent`, `chaptersCount` |

### 5.3. `/api/progress`

Endpoint:

- принимает `content_type`, `shikimori_id`, `season`, `episode`,
  `position_seconds`, `source`, `unit`, `progress_percent`, `locator`;
- понимает все шесть типов;
- для `unit = seconds` сохраняет позицию только после 5 секунд;
- для `percent`/`chapter`/`page` сохраняет и нулевую позицию — первая страница
  книги является законным местом остановки;
- делает upsert в `watch_progress` по
  `(user_id, content_type, shikimori_id)`;
- при `watched_episode` пишет в `watched_episodes`;
- при `completed` пишет в `user_list`;
- анонимному пользователю отвечает `200 { ok: false, reason: 'anon' }`, ничего
  не сохраняя.

`source` **не входит в уникальный ключ**. Это осознанно: сейчас один
`content_type` соответствует одному источнику. Если в будущем появятся два
источника книг одновременно, потребуется пересмотр ключа.

### 5.4. `readingProgress.ts`

Тонкая клиентская обёртка:

- не тянет серверные модули в браузер;
- отправляет `fetch` с `keepalive: true`;
- не ждёт ответа;
- глотает ошибку, чтобы потеря одной отметки не показывала ошибку поверх
  книги;
- по умолчанию `contentType = 'book'`, `unit = 'percent'`.

### 5.5. Восстановление позиции

- **Книга:** epub.js отдаёт CFI — точную позицию, независимую от размера окна
  и шрифта. FB2 хранит долю прокрутки.
- **Ранобэ:** позиция восстанавливается, если сохранённая глава совпадает с
  открытой; внутри главы — `scrollPercent`.
- **Манга:** аналогично, плюс номер страницы; для вертикальной ленты
  `scrollPercent` важнее номера.
- **Подкаст:** номер выпуска — позиция в RSS-фиде, отсортированном по дате
  возрастанию. Новые выпуски дописываются в конец и не сдвигают старые номера.

## 6. Подкасты

### 6.1. Источник и почему

Два источника:

1. **iTunes Search API** — каталог и поиск:
   - `collectionId` — внешний id, он же `shikimori_id`;
   - название, автор, обложка, жанр, страна, язык, `feedUrl`;
   - регион обязателен, поэтому в поиске есть выбор страны;
   - выбранный регион запоминается кукой `aw_podcast_region`.
2. **RSS самого шоу** — полный список выпусков:
   - читается на лету;
   - в БД не сохраняется;
   - короткий кэш разбора — `parseFeedCached` в `src/lib/podcasts.ts`.

Почему так: у популярного шоу могут быть сотни эпизодов, а хранить их все в
Postgres бессмысленно. iTunes даёт стабильный каталог, RSS — актуальные
выпуски.

### 6.2. Маршруты

| Адрес | Назначение |
|---|---|
| `/podcasts` | каталог, поиск, выбор региона |
| `/podcasts/[id]` | описание шоу и список выпусков |
| `/podcasts/listen/[id]/[episode]` | встроенный плеер |
| `/api/cron/reindex-podcasts` | пересборка каталога |

### 6.3. Индекс

`podcast_index` (миграция `0052`):

- `batch_id` + `collection_id` — составной первичный ключ;
- `title`, `author`, `description`, `artwork_original`, `genre`;
- `country`, `language`, `episode_count`;
- `rank`, `released_at`;
- триграммные GIN-индексы по `title` и `author`;
- индексы по активной партии, стране и дате.

Параметры сборки:

- 19 регионов;
- 4 базовых поисковых слова: `podcast`, `news`, `business`, `comedy`;
- до 200 записей за запрос (потолок iTunes);
- 4 поисковых слова на регион — около 76 запросов на всю партию;
- пауза 3,5 секунды между запросами;
- максимум 40 000 записей;
- минимальная здравая партия — 500;
- при усадке более чем на 20% активная партия не переключается;
- вставка пачками по 500.

Крон идёт примерно 10–20 минут, потолок задачи — 90 минут.

### 6.4. Поиск

- по своему индексу — триграммами, поэтому находится подстрока в названии и
  авторе;
- дополнительно — живой поиск iTunes по выбранному региону;
- это нужно, чтобы между ночными прогонами находились шоу, которых ещё нет в
  индексе.

### 6.5. Плеер

- обычный `<audio>`;
- аудио идёт через `/api/proxy/raw` с подписанной HMAC-ссылкой;
- прокси умеет `Range`/`206`, поэтому перемотка работает;
- на диске ничего не оседает;
- это решает mixed content (`http`-фиды на `https`-странице) и горячие ссылки
  CDN.

### 6.6. Прогресс

- `content_type = 'podcast'`;
- `source = null` — тип однозначно определяет источник;
- `unit = 'seconds'`;
- `episode` — позиция выпуска в фиде;
- номер выпуска считается по возрастанию даты: 1 — самый старый. Это важно:
  иначе новый выпуск сдвигал бы сохранённый прогресс на соседний эпизод.

### 6.7. Ограничения

- iTunes лимитирует примерно 20 запросов в минуту на IP;
- не все RSS-фиды отдают полный список или стабильные аудиоURL;
- аудиоCDN может требовать Referer или ограничивать хотлинк;
- «все регионы» ограничены 19 регионами iTunes, а не всей планетой;
- подкасты не имеют собственного рейтинга, поэтому «популярное» — это позиция
  в выдаче iTunes.

## 7. Книги

### 7.1. Источник и почему

Источник — **Флибуста через OPDS**:

- `/opds` — машиночитаемый Atom-контракт;
- не ломается от редизайна HTML-страниц;
- два зеркала: `flibusta.is` и `flibusta.site`;
- зеркала переключаются, если одно недоступно.

Файлы книг у себя **не хранятся**. EPUB/FB2 качаются с зеркала по требованию и
сразу отдаются пользователю.

### 7.2. Почему нужен `book_index`

У Флибусты **нет эндпоинта «книга по id»**:

- `/opds/book/{id}` отдаёт корневой каталог (проверено живьём 23.10.2026);
- поиск по числу ничего не находит;
- без своей записи карточка `/books/[id]` не открылась бы;
- «Продолжить чтение» и результаты поиска вели бы в никуда.

Поэтому `book_index` — не сменяемая партия, а **постоянный кэш лёгких
метаданных**:

- `book_id` — id Флибусты, он же `shikimori_id`;
- `title`, `author`, `annotation`, `genres`, `language`;
- `formats`, `size_bytes`, `downloads`, `year`;
- `cover_url`, `source_url`;
- `rank`, `in_catalog`, `updated_at`.

### 7.3. Наполнение индекса

Два пути:

1. **Ночной крон** `/api/cron/reindex-books`:
   - 40 страниц новинок по 20 книг — до 800;
   - 16 верхних жанров;
   - по 4 поджанра на жанр;
   - по 1 странице на поджанр;
   - пауза 700 мс между запросами;
   - максимум 8 000 книг;
   - минимальная здравая выборка — 100;
   - усадка более чем в 2 раза не применяется;
   - upsert пачками по 500;
   - всё, что не тронуто прогоном, получает `in_catalog = false`,
     `rank = null`, но остаётся в таблице.
2. **Живой поиск**:
   - `rememberBooks` делает upsert с `ignoreDuplicates: true`;
   - существующие строки не перезаписываются;
   - это позволяет открыть карточку книги, даже если её нет в текущей витрине.

### 7.4. Поиск и жанры

- поиск по индексу — триграммами по названию и автору;
- плюс живой OPDS-поиск;
- жанры — чипы из тех, что реально есть в витрине;
- витрина представительная, но не повторяет миллионы книг Флибусты;
- всё, чего нет в витрине, можно найти живым поиском.

### 7.5. Читатели

**EPUB** — `/books/read/[id]`:

- `epub.js` в `BookReader.tsx`;
- постраничная навигация;
- оглавление;
- три темы;
- клавиатура;
- позиция — CFI;
- файл отдаёт `/api/books/[id]/file` с
  `Content-Type: application/epub+zip`.

**FB2** — `/books/read/[id]/fb2`:

- сервер распаковывает `fb2+zip`;
- `src/lib/fb2.ts` собирает HTML;
- `Fb2Reader.tsx` показывает текст;
- позиция — доля прокрутки;
- иллюстрации в FB2-версии не показываются: это резервный путь, а не полный
  конвертер.

Почему два читателя: EPUB даёт точную позицию и хорошую вёрстку, но не у всех
книг есть EPUB. FB2 — запасной вариант, который можно собрать на сервере.

### 7.6. Прогресс

- `content_type = 'book'`;
- `source = 'flibusta'`;
- `unit = 'percent'`;
- `progress_percent` — доля 0..1;
- `locator` — `cfi` для EPUB или `scrollPercent` для FB2;
- «Продолжить читать» читает эти данные из `watch_progress`;
- в историю профиля книги не попадают: история строится по
  `watched_episodes`, то есть по сериям/выпускам, а не по позиции внутри
  книги.

### 7.7. Обложки

- обложки Флибусты — тяжёлые PNG (300–700 КБ);
- идут через `/api/proxy/raw` с подписью и ресайзом `?w=240|320|480`;
- если обложки нет — градиентная заглушка с первой буквой названия.

### 7.8. Ограничения

- OPDS-каталог Флибусты не является официальным API и может измениться;
- одно зеркало может лежать, второе — отвечать медленно;
- EPUB-конвертер Флибусты работает на лету; для некоторых книг EPUB может
  отсутствовать;
- FB2-читатель не показывает иллюстрации;
- правовой статус источника — тот же класс риска, что у видео-
  балансировщиков; это осознанное решение проекта, а не техническая
  случайность;
- книги в историю профиля не попадают — только в «Продолжить читать».

## 8. Ранобэ

### 8.1. Источник и почему

Источник — **Renovels** (`api.renovels.org`):

- публичный JSON API;
- отдаёт каталог, поиск, карточку, оглавление и текст главы;
- HTML-страницы сайта — клиентский Next.js, парсить их хрупко;
- у источника есть русские названия и большой каталог.

Адреса строятся по слагу `dir`, а не по числовому id:

- `/ranobe/[dir]`;
- `/ranobe/read/[dir]/[chapterId]`.

Причина: Renovels умеет отдать тайтл по `dir`, но **не по числовому id**.

### 8.2. Зачем свой индекс

`ranobe_index` (миграция `0055`) нужен по трём причинам:

1. ни одна сортировка каталога не даёт представительную витрину:
   - `-rating` выносит старьё;
   - `-views` — популярное;
   - `-count_chapters` — длинное;
2. поиск по подстроке должен работать независимо от доступности API;
3. карточки и «Продолжить» должны открываться, даже если источник временно
   недоступен.

### 8.3. Сбор витрины

Параметры `src/lib/ranobeIndex.ts`:

| Сортировка | Страниц |
|---|---:|
| `-views` | 12 |
| `-rating` | 8 |
| `-count_chapters` | 8 |
| `-id` | 4 |
| `-views` + категория «Новелла» (`196`) | 5 |

- 50 записей на страницу — проверенный максимум;
- пауза 250 мс;
- максимум 5 000 тайтлов;
- минимальная здравая выборка — 150;
- усадка более чем в 2 раза не применяется;
- upsert пачками по 500;
- старые строки не удаляются, а теряют `in_catalog`.

### 8.4. Что хранится

Только лёгкие метаданные:

- `title_id`, `dir`;
- `title`, `original_title`, `alternative_title`;
- `kind`, `status`, `year`;
- `rating`, `votes`, `views`, `chapters_count`;
- `cover_url`, `source_url`;
- `rank`, `in_catalog`, `updated_at`.

Описание, жанры и оглавление берутся live.

**Текст глав не хранится вообще.** Он запрашивается при открытии главы и сразу
очищается `sanitize-html`.

### 8.5. Чтение

`RanobeReader.tsx`:

- одна глава;
- прокрутка;
- выдвижное оглавление;
- переходы «назад/вперёд»;
- тёмная тема;
- позиция — номер главы + доля прокрутки.

Санитизация:

- разрешены только безопасные теги;
- `script`, `style`, `iframe` и опасные атрибуты вырезаются;
- ссылки — только `http(s)`/`mailto`, открываются в новой вкладке;
- картинки проходят через подписанный прокси;
- протокол-относительные URL запрещены;
- стили не парсятся.

### 8.6. Платные главы

- Renovels отдаёт `is_paid = true`;
- `content` пустой;
- обойти нельзя: текст физически не приходит без покупки;
- такие главы видны в оглавлении заблокированными;
- читатель не открывает их как обычные.

### 8.7. Прогресс

- `content_type = 'ranobe'`;
- `source = 'renovels'`;
- `unit = 'chapter'`;
- `episode` — индекс главы;
- `progress_percent` — общий процент по тайтлу;
- `locator`:
  `{ dir, chapterId, chapterIndex, chapterLabel, scrollPercent, chaptersCount }`.

### 8.8. Ограничения

- Renovels не отдаёт тайтл по числовому id;
- API может менять версии и поля;
- платные главы недоступны принципиально;
- описание и оглавление всегда live — при падении API карточка деградирует до
  индекса;
- поиск по своему индексу полноценно работает после первого
  `reindex-ranobe`.

## 9. Манга

### 9.1. Источник и почему

Источник — **Remanga** (`api.remanga.org`):

- публичный JSON API;
- каталог, поиск, карточка, оглавление, страницы главы;
- числовой id тайтла помещается в `bigint shikimori_id`;
- есть русские названия и большой каталог манги/манхвы/маньхуа.

Маршруты:

- `/manga`;
- `/manga/[dir]`;
- `/manga/read/[dir]/[chapterId]`;
- `/api/cron/reindex-manga`.

Тайтл открывается по слагу `dir`, потому что Remanga отдаёт карточку по слагу.

### 9.2. Индекс

`manga_index` (миграция `0056`):

- `title_id`, `dir`;
- `title`, `original_title`, `alternative_title`;
- `kind`, `status`, `year`;
- `rating`, `votes`, `views`, `chapters_count`;
- `cover_url`, `source_url`;
- `rank`, `in_catalog`, `updated_at`.

Сбор:

| Сортировка | Страниц |
|---|---:|
| `-views` | 20 |
| `-rating` | 14 |
| `-count_chapters` | 14 |
| `-id` | 8 |

- `PAGE_SIZE = 30` — проверенный максимум; на `count=32` Remanga отвечает
  `400`;
- пауза 250 мс;
- максимум 5 000 тайтлов;
- минимальная здравая выборка — 150;
- усадка более чем в 2 раза не применяется;
- upsert пачками по 500.

### 9.3. Карточка и главы

Карточка (`/api/titles/{dir}/`) даёт:

- `id`, `dir`, `main_name`, `secondary_name`, `another_name`;
- `description` (HTML, очищается до текста);
- `issue_year`, `avg_rating`, `total_votes`, `total_views`;
- `count_chapters`, `type`, `status`, `genres`, `categories`;
- `branches[0].id` — ветка для оглавления;
- `first_chapter.id`, `img`, `cover`.

Оглавление (`/api/titles/chapters/?branch_id=...`):

- по 100 глав на страницу;
- `index`, `chapter`, `tome`, `name`, `is_paid`, `is_free_today`;
- до короткой/пустой страницы;
- для длинных тайтлов страницы грузятся параллельно по 4;
- если последняя ожидаемая страница была полной, проверяется следующая — на
  случай, если `count_chapters` отстал.

Страницы главы (`/api/titles/chapters/{chapterId}/`):

- `content.pages` — массив групп картинок;
- каждая картинка: `link`, `width`, `height`;
- `content.title_id` присутствует;
- страницы **не хранятся**;
- URL подписываются через `/api/proxy/raw` и сразу отдаются в браузер.

### 9.4. Платные главы

- `is_paid = true` — глава заблокирована;
- запрос страниц отвечает `401`;
- читатель не ходит в API за страницами платной главы;
- в оглавлении показывается замок/пометка;
- если `is_free_today = true`, глава открывается как бесплатная;
- прогресс по заблокированной главе не сохраняется как прочитанный.

### 9.5. Читатель

`MangaReader.tsx`:

- вертикальная лента страниц;
- выдвижное оглавление;
- переходы «назад/вперёд»;
- тёмная тема;
- ленивая загрузка изображений;
- сохранение позиции при прокрутке;
- прогресс — глава + `scrollPercent` + номер страницы;
- общий процент тайтла — в `progress_percent`.

### 9.6. Проверено живьём

На момент сессии проверены:

- `martial_peak` — 3865 глав, 39 страниц по 100, параллельная загрузка за
  ~4 секунды, без ошибок;
- `solo-leveling_` — карточка и оглавление отдаются, платные главы помечаются;
- бесплатная глава `martial_peak` отдаёт страницы с `link`, `width`, `height`;
- поиск `магия` — 20 записей на страницу, 5 страниц;
- `count=30` — успешно, `count=32` — `400`;
- платная глава без покупки — `401`.

### 9.7. Ограничения

- Remanga — неофициальный API, может измениться без предупреждения;
- `count_chapters` может учитывать несколько веток;
- первый заход по неизвестному тайтлу при упавшем API даст 404; если тайтл уже
  в `manga_index`, показываются сохранённые метаданные;
- поиск по своему индексу появится после первого `reindex-manga`;
- страницы не кэшируются в БД: после перезагрузки глава запрашивается снова;
- сохранение прогресса требует миграции `0053`.

## 10. Навигация и интерфейс

### 10.1. Шапка

- добавлены «Подкасты», «Книги», «Ранобэ», «Манга»;
- порядок: аниме/кино → подкасты → книги → ранобэ → манга;

### 10.3. Общие элементы разделов

- карточка тайтла/шоу/книги;
- блок «Продолжить»;
- GET-форма поиска, чтобы результат можно было сохранить в закладки;
- пустые состояния и заглушки при отсутствии обложки;
- ошибки источника не показывают пользователю сырой JSON;
- ссылки на источник — только для атрибуции, чтение остаётся внутри сайта.

### 10.4. Стили

- добавлены стили вертикальной ленты манги (`.manga-scroll`);
- ограничена ширина ленты на очень широких экранах;
- читатели используют существующую тёмную палитру;
- EPUB-ридер поддерживает три темы;
- ранобэ и манга — тёмная тема по умолчанию.

### 10.5. Что ещё нужно проверить глазами

- 375px: семь элементов дока не переполняются;
- 1024–1279px: шапка не переполняется, подписи скрыты;
- 1280px+: подписи читаются, поиск не сжат;
- длинные названия не ломают карточки;
- оглавление манги на 3000+ глав не подвисает;
- платная глава показывает заглушку, а не пустой экран.

- файлы отдаются.

**Renovels** — проверено в рамках реализации:

- каталог, поиск, карточка, главы;
- текст главы приходит через API и санитизируется;
- платные главы имеют пустой `content`.

**iTunes** — проверено в рамках реализации:

- поиск по регионам;
- `collectionId` больше `int32`;
- RSS-фиды разбираются.

### 12.3. Что не проверено

| Проверка | Причина |
|---|---|
| Работа страниц под авторизацией | Нужна тестовая сессия; middleware редиректит на вход |
| Реальная запись прогресса книг/ранобэ/манги | Нужны применённые миграции `0053`–`0056` |
| Пересборка индексов в рабочей БД | Нет применённой схемы и доступа к рабочей БД |
| VPS-кроны | Нужен доступ к серверу |
| Кросс-девайс синхронизация чтения | Нужны две сессии и рабочая БД |
| Мобильная вёрстка на реальном устройстве | Проверено только по классам/коду |
| Полный прогон Flibusta/OPDS после индексации | Нужна рабочая среда |

### 12.4. Блокеры среды

- Supabase-ключи находятся только в резервном env-файле;
- DDL через REST недоступен;
- локальный `.env.local` содержит только `OPENROUTER_API_KEY`;
- без env нельзя поднять сайт в режиме, где работают Supabase-запросы;
- миграции `0053`–`0056` нельзя применить из песочницы.

Это означает, что «код готов» и «фича проверена в бою» — разные статусы.
Сейчас верно первое.

## 13. Анализ решений

### 13.1. Почему именно эти источники

| Раздел | Выбор | Альтернативы | Почему выбор оправдан |
|---|---|---|---|
| Подкасты | iTunes + RSS | Podcast Index, Spotify API | iTunes не требует ключа и даёт каталог по регионам; RSS — первоисточник выпусков |
| Книги | Flibusta OPDS | ЛитРес, Google Books | OPDS машиночитаем; большой каталог; EPUB/FB2; но правовой риск |
| Ранобэ | Renovels | Shikimori + MangaDex, Flibusta | Renovels отдаёт главы и текст; Shikimori не даёт текста |
| Манга | Remanga | MangaDex, Shikimori | Remanga отдаёт страницы глав и русские названия; меньше склейки |

Ранний план рассматривал Shikimori/MangaDex. В ходе сессии выяснилось, что для
встроенного чтения нужен источник, который отдаёт **страницы/текст**, а не
только метаданные. Поэтому чтение переехало на Remanga и Renovels, а не на
Shikimori.

### 13.2. Почему свой индекс, а не только live-запросы

Живой каталог источника:

- зависит от доступности API;
- не даёт быстрый поиск по подстроке;
- не гарантирует «Продолжить» для старых записей;
- может отдавать разные срезы в разных сортировках.

Свой индекс:

- один SQL-запрос вместо десятков сетевых;
- триграммный поиск;
- стабильная витрина;
- деградация вместо пустого экрана;
- возможность склеить несколько сортировок.

При этом индекс хранит только лёгкие метаданные. Тяжёлый контент (аудио,
EPUB/FB2, текст глав, страницы манги) остаётся у источника.

### 13.3. Почему у книг/ранобэ/манги нет `batch_id`

`batch_id` хорош для сменяемой партии. Но:

- у Флибусты нет карточки по id — запись в индексе нужна навсегда;
- у ранобэ и манги карточка тоже должна открываться после исчезновения из
  витрины;
- «Продолжить» ссылается на id, который может быть уже не в текущей партии.

Поэтому используется `in_catalog` + `rank`. Старые строки не удаляются, пока
не станет понятно, что они действительно не нужны. Это осознанный компромисс:
таблица растёт, зато ссылки не гниют.

### 13.4. Почему прогресс не стал отдельной сущностью

`watch_progress` уже:

- имеет правильный ключ;
- поддерживает `episode` и `season`;
- используется для «Продолжить»;
- синхронизируется между устройствами;
- покрыт RLS.

Добавление `unit`, `progress_percent`, `locator` и `source` дешевле, чем
новая таблица и перенос всех сценариев. Минус — семантика полей стала шире:
`position_seconds` у манги не секунды, а `unit` говорит, как его читать.

### 13.5. Почему у книг `percent`, а у манги `page`

- EPUB даёт CFI — точную позицию; процент — удобная агрегированная доля.
- FB2 не имеет стабильных страниц, поэтому доля прокрутки.
- Манга — вертикальная лента; «страница» условна, но номер полезен для
  отображения, а `scrollPercent` — для восстановления.
- Ранобэ — глава как единица, внутри — scroll.

Универсального числа для всех типов нет, поэтому `unit` + `locator` — более
честная модель, чем попытка всё свести к секундам.

### 13.6. Почему прокси, а не прямые ссылки

- mixed content: источник `http`, сайт `https`;
- hotlink-защита CDN;
- Range/206 для аудио;
- возможность ресайза обложек;
- сокрытие прямого адреса источника;
- единая точка для подписи и ограничения срока жизни ссылки.

Минусы:

- дополнительная нагрузка на сервер;
- зависимость от `PROXY_SIGNING_SECRET`;
- при отсутствии секрета локально ссылка прямая, и картинка может не
  загрузиться;
- прокси не должен становиться открытым релеем — подпись обязательна.

### 13.7. Почему поиск на триграммах

`pg_trgm`:

- уже используется в проекте;
- находит подстроку, а не только слово;
- не требует внешнего поискового движка;
- хорошо работает на небольших индексах (тысячи записей).

Ограничения:

- качество зависит от длины запроса;
- для очень больших каталогов может понадобиться ранжирование;
- поиск по индексу не заменяет живой поиск источника;
- «реализация ии» с пробелом зависит от токенизации и ILIKE/сходства.

### 13.8. Почему платные главы не обходятся

Обход был бы:

- технически хрупким;
- юридически рискованным;
- нечестным по отношению к источнику и авторам;
- всё равно неполным: без покупки сервер не отдаёт контент.

Правильное поведение — показать, что глава существует, но недоступна. Это
сохраняет UX и не создаёт иллюзию взлома.

### 13.9. Сильные стороны реализации

- единая модель прогресса;
- отсутствие дублирования контента;
- деградация до индекса;
- переиспользование прокси;
- понятные state-таблицы;
- предохранители от пустой витрины;
- аккуратная работа с длинными оглавлениями;
- санитизация HTML;
- явные ограничения в документации.

### 13.10. Слабые места

- четыре разных источника — четыре точки отказа;
- неофициальные API могут измениться;
- индекс и live-данные могут расходиться;
- книги/ранобэ/манга в основном русскоязычные, требование «все регионы»
  выполнено не полностью;
- платный контент недоступен;
- правовой статус Flibusta/Remanga/Renovels требует отдельной оценки;
- нет фонового обновления прогресса при закрытии вкладки для всех читателей?
  `keepalive` есть, но поведение нужно проверить в реальном браузере;
- `source` не входит в ключ прогресса — при будущем мультиисточнике возможны
  коллизии;
- книги не попадают в историю профиля;
- нет офлайн-режима.

## 14. Риски

| Риск | Вероятность | Влияние | Смягчение |
|---|---|---|---|
| Remanga/Renovels меняют API | Средняя | Высокое | live-запросы, индекс, таймауты, логи, graceful degradation |
| Flibusta недоступна | Средняя | Высокое | два зеркала, индекс, live-поиск |
| iTunes rate limit | Средняя | Среднее | пауза 3,5 с, партия, 19 регионов |
| Платная глава не открывается | Высокая | Ожидаемо | честная заглушка, `is_free_today` |
| Миграции не применены | Высокая | Блокер | применить `0051`–`0056` по порядку |
| Ключи env отсутствуют | Высокая | Блокер | восстановить `.env.local` из резервной копии |
| Индекс пуст после первого запуска | Средняя | Среднее | `MIN_SANE`, не переключать витрину |
| Долгое оглавление манги | Средняя | Среднее | 100/стр., параллельно по 4, предохранитель 60 стр. |
| Ошибка в `locator` ломает «Продолжить» | Средняя | Среднее | валидация, восстановление только при совпадении главы |
| Правовые претензии к источникам | Низкая/средняя | Высокое | оценить политику проекта, атрибуция, не хранить файлы |
| XSS из HTML ранобэ | Низкая | Высокое | `sanitize-html`, белый список тегов |
| Открытый прокси | Низкая | Высокое | HMAC-подпись, срок жизни, ограничение сырого прокси |
| Потеря прогресса при закрытии вкладки | Средняя | Низкое | `keepalive`, периодическое сохранение |

## 17. Краткая справка по API источников

### 17.1. iTunes

```http
GET https://itunes.apple.com/search?term=podcast&country=ru&media=podcast&entity=podcast&limit=200
```

- `collectionId` — id шоу;
- `feedUrl` — RSS;
- `country` обязателен;
- лимит ~20 запросов/мин на IP.

### 17.2. Flibusta OPDS

```http
GET https://flibusta.is/opds
GET https://flibusta.is/opds/new/{page}/new
GET https://flibusta.is/opds/search?searchType=books&searchTerm=...&pageNumber=0
GET https://flibusta.is/opds/genres
GET https://flibusta.is/opds/genres/{жанр}
```

- книги: `/b/{id}/epub`, `/b/{id}/fb2`;
- `/opds/book/{id}` не является карточкой книги;
- зеркала: `flibusta.is`, `flibusta.site`.

### 17.3. Renovels

```http
GET https://api.renovels.org/api/search/?query=...&count=24&page=1
GET https://api.renovels.org/api/search/catalog/?ordering=-views&count=50&page=1
GET https://api.renovels.org/api/titles/{dir}/
GET https://api.renovels.org/api/v2/titles/chapters/?branch_id={id}&count=500&page=1&ordering=index
GET https://api.renovels.org/api/v2/titles/chapters/{chapterId}/
```

- карточка — по `dir`, не по числовому id;
- текст главы — только live;
- платная глава — `is_paid = true`, пустой `content`.

### 17.4. Remanga

```http
GET https://api.remanga.org/api/search/catalog/?count=30&page=1&ordering=-views
GET https://api.remanga.org/api/search/?query=...&page=1
GET https://api.remanga.org/api/titles/{dir}/
GET https://api.remanga.org/api/titles/chapters/?branch_id={id}&count=100&page=1&ordering=index
GET https://api.remanga.org/api/titles/chapters/{chapterId}/
```

- каталог: максимум 30 записей;
- поиск: 20 записей на страницу;
- главы: 100 на страницу;
- платная глава: `401`;
- `content.pages` — массив групп изображений.

## 20. Итог сессии 1

Сессия закрыла большой кусок продукта: MediaWatch перестал быть только
видеосервисом. Появились подкасты, книги, ранобэ и манга — с каталогами,
поиском, встроенными читателями, единым прогрессом и ночными индексами.

Главное решение — **не хранить тяжёлый контент и не строить вторую
архитектуру**. Источники отдают метаданные и контент по запросу; сайт хранит
только достаточно, чтобы каталог, карточка и «Продолжить» работали быстро и
переживали временную недоступность источника.

Главное ограничение — **платные главы и региональный охват**. Первое нельзя
обойти технически, второе зависит от выбранных источников. В отчёте это
зафиксировано честно, без обещаний «доступа ко всему».

Следующий практический шаг — не писать новый код, а:

1. применить миграции;
2. поднять сайт с полным env;
3. прогнать четыре пересборки;
4. проверить разделы под тестовым пользователем;
5. настроить VPS-кроны.

После этого можно считать расширение не только собранным, но и введённым в
эксплуатацию.

### 21.3. Архитектура: каноническая ось

```
карточка / читатель
        │
        ▼
   resolve.ts
        ├── title_sources      (где тайтл лежит в источнике)
        ├── canonical_chapters (общая ось глав)
        └── chapter_sources    (где глава бесплатна)
        │
        ▼
 remanga | mangadex | mangalib | selfmanga | mintmanga | renovels | flibusta
        │
        ▼
 watch_progress (episode = canonical idx)
```

Ключевые решения:

- **`title_key`, а не `shikimori_id`.** В существующей схеме `shikimori_id`
  хранит id источника (Remanga/Renovels/Флибуста). В новых таблицах колонка
  называется честно.
- **`canonical_chapters` + `chapter_sources`.** У источников разная нумерация;
  прогресс нельзя ключевать номером главы источника.
- **`variant`.** Том Флибусты, язык/группа MangaDex — разные строки.
- **`tome`.** «Том 2, глава 1» не сливается с «том 1, глава 1».
- **`idx` как `episode`.** Стабильная позиция для «Продолжить».
- **`chapterNo` + `tome` в `locator`.** Если в середину вставят главу и `idx`
  сдвинется, позиция всё равно восстановится по номеру.

Подробности — в `PLAN-GRAY-SOURCES.md` §4.

### 21.5. Как работает манга

Гибридный режим:

1. Карточка читает только **сохранённое** каноническое оглавление.
2. Если его нет — показывает Remanga и запускает `CanonicalBootstrap`.
3. Bootstrap делает `POST /api/sources/resolve` с `external_id` (Remanga `dir`),
   затем `router.refresh()`.
4. Резолвер:
   - пишет seed Remanga;
   - ищет MangaDex/MangaLib/SelfManga;
   - сливает главы в `canonical_chapters`;
   - заполняет `chapter_sources`.
5. Карточка показывает бейджи `RM` / `MD` / `ML` / `SM`.
6. Читатель выбирает источник:
   - `?source=` если указан;
   - иначе приоритет реестра;
   - первый бесплатный;
   - если все платные — заглушка.

Маршруты:

```text
/manga/read/[dir]/[idx]                 # авто
/manga/read/[dir]/[idx]?source=mangadex # явно
```

Старые ссылки `/read/[dir]/[chapterId]` редиректят на `idx` через
`chapter_sources`.

Прогресс:

```json
{
  "source": "mangadex",
  "chapterKey": "uuid",
  "idx": 12,
  "chapterNo": "21.2",
  "tome": 2,
  "scrollPercent": 0.18,
  "page": 3
}
```

### 21.6. Ранобэ + Флибуста

- Renovels остаётся источником глав.
- Флибуста — источником томов (EPUB).
- Крон `link-ranobe-flibusta` ищет том по названию/году и пишет
  `title_sources` с `variant = book-{id}`.
- Карточка ранобэ показывает «Читать томами» → `/books/read/[id]`.
- Прогресс тома — `book`/`percent`, глав — `ranobe`/`chapter`; это две
  независимые записи, в «Продолжить» их нужно дедуплицировать по названию.

`RanobeReader` сознательно не переведён на каноническую ось: Renovels —
единственный источник глав, выигрыша сейчас нет.

### 21.9. Найденные баги и исправления

| Проблема | Исправление |
|---|---|
| `shikimori_id` — не Shikimori | в новых таблицах `title_key`; маппинг по названию/году |
| Нет канонической оси | `canonical_chapters` + `chapter_sources` |
| `unique (…, source)` не вмещал тома | добавлен `variant` |
| `idx` сдвигается при вставке главы | в `locator` добавлены `chapterNo` и `tome` |
| MangaDex `at-home` живёт ~15 мин | кэш `baseUrl` ≤ 10 мин, файлы — дольше |
| Динамический CDN MangaDex | allowlist по суффиксам, не по точным хостам |
| MangaDex `/chapter?limit=500` → `400` | **`limit` максимум 100**; адаптер и замер исправлены |
| MangaLib-картинки без Referer → 403 | `signRawUrl` с `Referer: https://mangalib.me/` |
| MintManga HTML без Referer → 404 | Referer в адаптере |

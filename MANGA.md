# MediaWatch — манга: справка, решения и статус

Обновлено: 23.10.2026

Статус: **код готов и собирается**. Миграции `0053`–`0056` в рабочей среде
ещё не применены, поэтому финальная проверка под авторизованным
пользователем и ночная пересборка каталога остаются ручными шагами.

---

## 1. Справка

### 1.1. Что это

«Манга» — шестой самостоятельный раздел MediaWatch. Он идёт после
подкастов, книг и ранобэ:

**Подкасты → Книги → Ранобэ → Манга**

Раздел умеет:

- показывать каталог манги, манхвы и маньхуа;
- искать по подстроке названия, в том числе по оригинальному и
  альтернативному названию;
- открывать карточку тайтла с описанием, жанрами, рейтингом и оглавлением;
- читать бесплатные главы прямо на сайте;
- сохранять место чтения и показывать «Продолжить читать»;
- честно помечать платные главы, не пытаясь обойти источник.

### 1.2. Маршруты

| Адрес | Назначение |
|---|---|
| `/manga` | каталог, поиск, фильтр по типу, «Продолжить читать» |
| `/manga/[dir]` | карточка тайтла и оглавление |
| `/manga/read/[dir]/[chapterId]` | встроенный читатель главы |
| `/api/cron/reindex-manga` | пересборка витрины каталога |
| `/admin/status` | состояние индекса и ручной запуск пересборки |

Адрес строится по слагу `dir`, а не по числовому id: Remanga отдаёт карточку
по слагу (`/api/titles/{dir}/`), а не по числовому id.

### 1.3. Что видит пользователь

- Сетку карточек с обложкой, типом, годом, числом глав и рейтингом.
- Поиск обычной GET-формой: результат можно сохранить в закладки.
- Карточку тайтла с кнопкой «Начать читать» или «Продолжить».
- Вертикальную ленту страниц без внешних переходов на чтение.
- Выдвижное оглавление, переходы «назад/вперёд», сохранение позиции.
- Пометку «платно» у недоступных глав и отдельную заглушку в читателе.
- Если источник временно недоступен — сохранённые метаданные из индекса,
  вместо 404, для тайтлов, которые уже попадали в индекс.

### 1.4. Источник данных

Источник — **Remanga** (`https://api.remanga.org`).

Почему Remanga:

- публичный JSON API без ключа;
- есть каталог, поиск, карточка, оглавление и страницы глав;
- числовой id тайтла помещается в существующий `bigint shikimori_id`;
- есть русские названия и большой каталог манги/манхвы/маньхуа.

Платные главы Remanga отдают `is_paid = true`, а запрос их страниц отвечает
`401`. Обойти это невозможно: картинки физически не приходят без покупки.
Раздел не пытается обходить защиту — он показывает такие главы
заблокированными.

## 2. Принятые решения

| Решение | Почему так |
|---|---|
| Источник — Remanga, а не Shikimori/MangaDex | У Remanga есть готовые страницы глав, поиск и карточки; числовой id ложится в существующий `shikimori_id` |
| Не заводить отдельную таблицу `content_items` | Для манги достаточно существующих `watch_progress`/`user_list`; числовой id Remanga уникален и помещается в `bigint` |
| Маршруты по `dir`, а не по id | Remanga не умеет отдавать тайтл по числовому id, только по слагу |
| Хранить только лёгкие метаданные | В БД попадают id, слаг, названия, тип, год, рейтинг, голоса, просмотры, число глав и обложка. Описание, жанры, оглавление и страницы — live |
| Страницы глав не хранить вообще | Это самый тяжёлый контент; они запрашиваются при открытии главы, подписываются через прокси и сразу уходят в браузер |
| Свой индекс `manga_index` | Нужен для быстрого каталога, поиска по подстроке и «Продолжить», когда API источника недоступен |
| Витрина из нескольких сортировок | Одна сортировка Remanga даёт смещённый срез: `-rating` — старьё, `-views` — популярное, `-count_chapters` — длинное. Витрина склеивает несколько проходов |
| Поиск по подстроке через `pg_trgm` | Покрывает название, оригинальное и альтернативное название, не требуя внешнего поискового движка |
| Читатель — вертикальная лента | Для манги это привычнее постраничного режима; главы у источника независимы |
| Прогресс — глава + доля прокрутки | Позиция внутри главы не выражается одним номером страницы; в `locator` хранится `scrollPercent`, а `progress_percent` — общий процент по тайтлу |
| Платные главы не запрашивать | Если Remanga всё равно ответит `401`, показывать заглушку; не делать вид, что защита обойдена |
| `is_free_today` открывает главу | Если источник сам сделал платную главу бесплатной сегодня, она читается на общих основаниях |
| Подписи навигации — с `xl` | После добавления манги в шапке семь пунктов; на 1024–1279px подписи и поиск уже не помещались |
| Нижний док — `text-[10px]` | На 375px семь элементов помещаются только при уплотнённых подписях |

## 3. Что сделано

### 3.1. База данных

Создана миграция:

- `supabase/migrations/0056_manga_index.sql`

Она добавляет:

- `manga_index` — лёгкие метаданные витрины;
- `manga_index_state` — состояние ночной пересборки;
- триграммные индексы по названиям;
- индекс витрины `(rank nulls last) where in_catalog`;
- индекс фильтра по типу;
- RLS и `select` для `authenticated`/`anon`.

Схема прогресса расширяется миграцией `0053_books.sql`:

- `content_type` поддерживает `book`, `manga`, `ranobe`;
- `source` хранит `remanga`;
- `unit` поддерживает `page`;
- `progress_percent` и `locator` используются для чтения.

> Важно: миграции `0053`, `0054`, `0055`, `0056` нужно применить вручную.

### 3.2. Серверная часть

Созданы модули:

- `src/lib/mangaShared.ts` — клиентобезопасные типы, ссылки и подписи глав;
- `src/lib/manga.ts` — API Remanga, нормализация, поиск, каталог, карточка,
  оглавление, страницы, индексные запросы и `rememberManga`;
- `src/lib/mangaIndex.ts` — сбор витрины из нескольких сортировок, upsert и
  очистка старых записей.

Особенности реализации:

- каталог Remanga отдаёт **максимум 30 записей** на страницу; на `count=32`
  источник отвечает `400`;
- поиск Remanga отдаёт по 20 записей на страницу, `limit` игнорируется;
- оглавление — по 100 глав на страницу, до короткой/пустой страницы;
- для длинных тайтлов страницы оглавления грузятся параллельно по 4;
- если последняя ожидаемая страница оглавления была полной, код проверяет
  следующую — на случай, если `count_chapters` отстал;
- обложки и страницы подписываются через `/api/proxy/raw`;
- при отсутствии `PROXY_SIGNING_SECRET` используется прямой URL;
- ошибки источника не кэшируются: пустой ответ не залипает на полчаса.

Проверено вживую:

- `martial_peak` — 3865 глав, 39 страниц по 100, параллельная загрузка за
  ~4 секунды, без ошибок;
- `solo-leveling_` — карточка и оглавление отдаются, платные главы
  помечаются корректно;
- бесплатная глава `martial_peak` отдаёт страницы с `link`, `width`, `height`;
- поиск `магия` — 20 записей на страницу, 5 страниц;
- `count=30` — успешно, `count=32` — `400`.

### 3.3. Интерфейс

Созданы страницы:

- `src/app/manga/page.tsx` — каталог, поиск, чипы типов, «Продолжить»;
- `src/app/manga/[dir]/page.tsx` — карточка, описание, оглавление, платные
  главы;
- `src/app/manga/read/[dir]/[chapterId]/page.tsx` — сборка читателя,
  восстановление позиции, платные главы без запроса страниц.

Созданы компоненты:

- `MangaCard.tsx` — карточка тайтла;
- `MangaContinue.tsx` — блок «Продолжить читать»;
- `MangaSearchBar.tsx` — поисковая GET-форма;
- `MangaReader.tsx` — вертикальная лента, оглавление, навигация, сохранение
  прогресса.

Навигация:

- «Манга» добавлена в `HeaderNav` и `MobileDock`;
- порядок разделов сохранён: подкасты → книги → ранобэ → манга;
- в шапке подписи показываются с `xl`;
- в нижнем доке подписи уменьшены до `text-[10px]`.

Стили:

- добавлены `.manga-scroll` и ограничение ширины ленты на очень широких
  экранах.

### 3.4. Прогресс

`src/lib/readingProgress.ts` поддерживает мангу:

- `contentType: 'manga'`;
- `unit: 'page'`;
- `episode` — номер главы в оглавлении;
- `progress_percent` — общий процент по тайтлу;
- `locator`:

```json
{
  "dir": "solo-leveling_",
  "chapterId": 120199,
  "chapterIndex": 1,
  "chapterLabel": "Глава 1",
  "page": 3,
  "pagesCount": 42,
  "scrollPercent": 0.18,
  "chaptersCount": 38
}
```

`/api/progress` сохраняет `progress_percent` для `unit='page'`.

Позиция восстанавливается только если сохранённая глава совпадает с
открытой; иначе новая глава начинается с начала.

## 5. Техническая справка по Remanga

### Каталог

```http
GET https://api.remanga.org/api/search/catalog/?count=30&page=1&ordering=-views
```

Допустимые сортировки:

- `-views`
- `-rating`
- `-count_chapters`
- `-id`

Ограничения:

- `count` — максимум **30**;
- `count=32` и выше — `400`;
- пагинация 1-based.

### Поиск

```http
GET https://api.remanga.org/api/search/?query=магия&page=1
```

- 20 записей на страницу;
- `props.total_items`, `props.total_pages`, `props.page`;
- `limit`/`count` поиск игнорирует.

### Карточка

```http
GET https://api.remanga.org/api/titles/{dir}/
```

Используются:

- `id`, `dir`, `main_name`, `secondary_name`, `another_name`;
- `description` (HTML, очищается до текста);
- `issue_year`, `avg_rating`, `total_votes`, `total_views`;
- `count_chapters`, `type`, `status`, `genres`, `categories`;
- `branches[0].id` — ветка для оглавления;
- `first_chapter.id`, `img`, `cover`.

### Оглавление

```http
GET https://api.remanga.org/api/titles/chapters/?branch_id={id}&count=100&page=1&ordering=index
```

- по 100 глав на страницу;
- `index` — порядковый номер;
- `chapter` — номер главой строкой (`0`, `1`, `1.1`);
- `tome`, `name`, `is_paid`, `is_free_today`.

### Страницы главы

```http
GET https://api.remanga.org/api/titles/chapters/{chapterId}/
```

- `content.pages` — массив групп картинок;
- каждая картинка: `link`, `width`, `height`;
- `content.title_id` присутствует;
- платная глава без покупки — `401`.

### Обложки

- `img.high` обычно содержит `/media/...`;
- `cover.high` может быть без `/media/`;
- приоритет — `img`, затем `cover`;
- относительный путь без `/media/` получает префикс
  `https://remanga.org/media/`.

## 7. Ограничения и риски

- **Remanga — неофициальный API.** Он может измениться без предупреждения;
  поэтому есть кэш, таймауты и деградация до индекса.
- **Платные главы недоступны принципиально.** Это не баг и не временное
  ограничение: страницы не отдаются источником.
- **Счётчик `count_chapters` может учитывать несколько веток.** Поэтому
  загрузка глав останавливается на пустой пачке и проверяет дополнительную
  страницу, если последняя была полной.
- **Первый заход по неизвестному тайтлу при упавшем API даст 404.** Если
  тайтл уже есть в `manga_index`, показываются сохранённые метаданные.
- **Поиск по своему индексу появится после первого `reindex-manga`.**
  До этого работает живой поиск Remanga.
- **Сохранение прогресса для манги требует миграции `0053`.** Без неё
  constraint в `watch_progress` не пропустит `content_type = 'manga'`.
- **Страницы хранятся только в ответе.** Их URL не кэшируются в БД, поэтому
  после перезагрузки глава запрашивается у источника снова.
